# Base Graph v1.8 TDD and promotion protocol

Use this protocol for deterministic development, exams, replay diagnosis,
Bench v7, and promotion decisions.

## Architecture invariant matrix

Keep every inherited Base/v1.7 suite green and add v1.8 cases for:

1. v1.7 Adapter stacks select identically when no v1.8 hook is supplied.
2. goal stages validate forward/recovery transitions and current context.
3. matchup board targets declare counts, deadline, owner, and reservations.
4. every macro root is currently Base-legal and bound to a current goal.
5. stale goal, macro, threat, constraint, score, or future evidence is ignored.
6. persisted plan memory never reuses bindings, constraints, or scores.
7. unproved/incomplete/private dominance constraints have no authority.
8. proved dominance cannot filter mandatory or terminal actions.
9. an all-removed constraint restores the full input frontier.
10. future evidence covers exactly two public turns and current action IDs.
11. expected, worst, lower bound, confidence, and branch count are finite.
12. timeout/unsupported/private/incomplete future evidence falls back.
13. tactical, future, and learned ranking never crosses Base hard tiers.
14. execution exam ignores action order but matches final public field and hand.
15. counterfactual outcome exam is isolated and never a runtime feature.
16. fixed public input produces identical context, plan, masks, evidence,
    selection, fallback, and audit ID.
17. trace v2 auditor accepts positive fixtures and rejects each violation.

## Deck and Adapter fixtures

Cover weak openings, alternate/recovery attackers, energy deficits, Bench
capacity, search/discard targets, evolution timing, resource conflicts, retreat/
switch costs, terminal attacks, gust/prize order, one-prize buffers,
disruption recovery, and every interaction type.

For each important choice include positive, negative over-trigger, boundary,
metamorphic, stale-context, timeout, and exception scenes. For matchup behavior
include unique, ambiguous, and unknown belief variants. Assert owner, goal stage,
macro route, mask transition, proof/future evidence, and final selection.

## Exam construction

Build replay-derived execution exams from winning expert scenes without forcing
the expert's action order. Score correct only when the final public field and
final hand match exactly. Keep legal alternative orderings correct.

Build counterfactual exams separately. From one identical public prefix,
execute legal sibling routes under paired continuation seeds. Preserve branch
probability, expected result, worst case, standard error/confidence, and trace.
Do not reuse discovery/confirmation seeds for label creation.

## Local process safety

Before training, benchmark, replay, simulation, or evaluation:

- inspect active Python commands and do not overlap a heavy run;
- require at least 12 GiB available physical RAM and commit below 70%;
- use at most `--workers 4`;
- leave all `PTCGABC_MAX_*` safeguards unchanged.

Treat watchdog/capacity abort as `infra_invalid`.

## Evidence isolation

Freeze mutually disjoint populations:

- `training_oracle`: replay mining, exams, branch labels, fitting, thresholds,
  and certificates;
- `discovery_200`: one evaluation of the frozen candidate;
- `confirmation_800`: final evaluation of the unchanged candidate.

Record materialized `run_seed` and `(pair_id, run_seed)` identities. Any
candidate change after discovery consumes that family.

## Discovery and confirmation

Run the 200-game weighted discovery gate on untouched seeds. Require zero
invalid games, declared owner/goal/macro flips, clean trace/exam audits, and no
protected regression. Architecture candidates should show at least `+0.02`,
four candidate-only flips, and zero baseline-only flips before spending the
confirmation budget.

Run the unchanged candidate on the 800-game confirmation contract across:

- `ladder_weighted`;
- `top10_frontier`;
- `strong_policy_anchors`.

Require a positive paired confidence lower bound on the weighted lane, every
suite minimum, zero dirty/invalid games, no protected archetype/frontier/anchor
regression, unchanged hashes, and a passing isolation audit.

Exact no-op is reject. Positive but insufficient evidence is hold. Passing
gates makes a candidate promotion-eligible; champion replacement or external
submission still requires explicit user authorization.
