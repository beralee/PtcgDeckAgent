# 宝可梦专属战斗演出 · Windows v0.6.2

本轮将 13 只角色的出场、蓄力、移动、命中、余韵拆成各自的演出时间线，并新增沙奈朵的模型与精神拥抱特性演出。版本号保持 v0.6.2。演出是根据宝可梦特征创作的游戏内表现，不是复刻或导入官方动画。

## 实现边界

`ArenaPokemonDirection` 给出每个物种的确定性位置、朝向、隐藏时段、命中点、结果揭示时刻和结束时刻。`ArenaPokemonStageVfx` 按同一个演出时钟构建有上限的场景几何。模型关节动作与音效同时跟随这条时间线；普通速度约 2.8–3.85 秒，加速模式整体缩短。

`ArenaSignatureVfx` 只接收公开显示数据和已提交的目标坐标。沙奈朵由 `ArenaPokemonAbilityCue` 在真实 USE_ABILITY 后，从同一公开卡牌的前后变化确认“超能量 +1、伤害 +20”。替换、隐藏、模糊目标和单纯手动附能不触发。连续精神拥抱排队播放，后续短脉冲加速，避免多个模型重叠。

`ArenaMotionDirector` 控制结果揭示、下一回合摸牌和交互恢复；关闭动画、切换场景或布局重置会清理角色、音效、灯光和相机偏移。静音设置有效。新增沙奈朵为约 3.95 万三角面、45 个网格部件的可编辑 GLB，包含独立裙摆、手臂、手部、头部和胸前核心。Python、Blender 只在开发时使用。

卡牌规则、策略接口、隐藏信息边界没有改变。Android/Web 仍使用原有 2D 路径；新增模型、音效均位于现有导出排除的 `assets/arena3d/**` 树内。此次工作是表现层验证，不是 CABT 引擎对齐或策略性能验收。

## 验证与录像

新增失败用例先覆盖专属路径与沙奈朵入口，再实现功能。8 个相关 TestBase 套件共 40 个测试通过，包括 14 段真实规则交互、连续精神拥抱、隐藏信息防护、静音、快速播放、关闭动画、清理、摸牌排队及平台入口。另以 Windows 渲染器运行专属演出套件和投影、清理、可读性、平台独立检查。

录制工具 `ArenaCombatShowcaseRunner.gd` 设置初始局面，然后提交实际招式和特性，经过正常游戏规则及呈现链路。它不是自主进行的完整对局。14 段都检查提交成功、正确角色、真实结算、演出完成和 AI 没有出现人类选择界面。正常速度，无模型转台，约 96 秒，1600×900 / 60 FPS。

发行模板不支持开发器的命令行脚本覆盖，因此 Windows 包中的 `Play-Battles.cmd` 通过既有本地验收入口传入 `--arena-acceptance --arena-3d --arena-combat-showcase`，由 `ArenaLobby` 加载同一个演出工具。普通启动不进入展示模式。

结果保存在 `output/arena3d-personality/20260929/`：视频、逐段结果、校验摘要和三组画面检查表。工作证据在忽略目录 `.tmp/arena-personality-20260929/`。最终视频全程解码，并检查非静音及峰值；这些检查不等同于所有设备的现场试听。

## 回退

本轮修改前文件逐个备份在 `.tmp/arena-personality-20260929/before/`，路径分隔符用 `__` 编码。回退时仅逐个恢复本轮对应文件，保留工作区内其他修改。恢复旧声音可使用该备份中的声音生成器重新生成；删除本轮新增的沙奈朵入口及新增 Direction/StageVfx/AbilityCue 前，先恢复调用方。不要对整个未提交工作区执行批量还原。录制工具不会改变普通游戏启动流程。
