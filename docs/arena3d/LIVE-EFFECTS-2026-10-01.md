# 安卓实际对局动画漏播修复

用户反馈 v20 的支援者和宝可梦演出仍不出现。本次重新从正式 APK 的普通入口检查，
不能用资源预览可播放代替实际对局验收。

## 已复现原因

1. `ArenaBattlePresenter.setup()` 只在安装当下连接 `_gsm.action_logged`。
   策略包对局在校验包时异步等待，安装 presenter 时 `_gsm` 仍为空；后续创建引擎没有重新绑定。
   `ArenaLiveEntry` 在修复前确认：真实支援者和攻击均提交成功，但演出计数分别为 0。
2. 3D 动画使用 `arena_visuals.cfg` 的 `motion`；准备页面的动画按钮只修改旧 2D 设置。
   保存过 `motion=false` 的玩家即使点击“开启”，3D 仍关闭；移动端没有桌面设置入口可以恢复。
   修复前的第二个回归测试确认这个问题。

普通经典 AI 路径并非全部失效：v20 正式 ARM64 APK 在模拟器内从主菜单正常进入，
实际使用“莉莉艾的决心”可播放。证据 `lillie-v20.mp4` / `lillie-early.png` 保存在本地工作目录。
尚未获得用户手机的具体模式、卡牌和存档，不能把模拟器复现等同于已读取手机故障。

## 修复

- 通过战斗场景已有的 `_on_action_logged` 转发 3D 事件，复用每个 GSM 的连接和释放生命周期。
  移除 presenter 的一次性独立订阅。同步、异步和替换引擎均只转发一次；保留原动作处理顺序。
- 准备页面读取、显示、修改所选场地实际使用的动画偏好；切换场地后同步按钮状态。
  3D 和 2D 的保存偏好继续独立，明确关闭动画仍然有效。
- Android 诊断新增 `arena_live`：安装经真实校验的本地策略包，经准备页面启动真实策略对局，
  观察 presenter 先于 GSM 安装；随后仅替换可重复的公开牌面，通过触摸支援者“使用”和攻击按钮验证演出。
  不直接调用动画导演，不在战斗中强制开启 motion，不把测试牌面声称为自然洗牌结果。

本轮没有新增模型、纹理或提高轻量渲染预算，不修改规则、策略权限或网络行为。

## 手机 DeepSeek 展示

按追加反馈，触摸模式的台词移到屏幕中上方，短暂覆盖对手备战区，正文从固定 18 像素改为
随手机 UI 缩放的 22 号基准字号。1080×1920 为 53 像素、1920×1080 为 49 像素。

保留正文大小并压低高度。桌面仍使用原来的右侧小气泡。
对话框主体继续让点击穿透，模态窗口与镜头演出时隐藏；不移动牌桌，不增加模型请求。
