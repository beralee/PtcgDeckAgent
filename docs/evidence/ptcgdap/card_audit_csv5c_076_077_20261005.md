## 缺陷与最小修复

`EffectRegistry` 既没有这两个效果 ID 的精确注册，也没有其中文招式的动态路由。真实 API 数据可以解析、普通费用和印刷伤害可以执行，但鬼斯不抽牌、鬼斯通不施加睡眠；`CardImplementationStatus` 因此将两张卡标为未实现。

仅在 `scripts/engine/EffectRegistry.gd` 增加两条精确 effect ID 分支：

- 鬼斯使用现有 `AttackDrawCards(1, 0)`，只绑定第 0 个招式。第 1 招仍是普通 20 伤害，不能连带抽牌。
- 鬼斯通使用现有 `EffectApplyStatus("asleep", false, 0)`，不为施加睡眠掷币。睡眠状态继续经过共享保护与状态互斥规则，回合间检查正常掷币决定是否醒来。

消费者已追踪到 `GameStateMachine.use_attack`、`EffectProcessor.execute_attack_effect`、实际抽牌日志和 `process_pokemon_check`。没有修改共享抽牌、状态、伤害或 Host 实现；同名「吸引」在其他印刷版本的抽牌数量不受这两条精确注册影响。

## 验证

环境：Windows，Godot `4.6.1.stable.official.14d19694e`。所有测试串行、隔离用户目录运行。

新增专项 `tests/test_csv5c_076_077_audit.gd`：9/9，通过以下实际规则与入口：

1. 源打印属性、动态加载后的注册类型、状态标记和招式索引。
2. 双座位吸引抽恰好顶牌 1 张、保留剩余顺序和正确的攻击来源日志；对手只有正常回合开始抽牌。
3. 空牌库或最后 1 张时效果尽力执行，不错误触发立即抽空败北。
4. 无能量、缺恶能量或总费用不足时拒绝攻击且无抽牌、伤害或状态副作用。
5. 双座位磷火造成 20 且不抽牌。
6. 双座位黑色微寐先施加睡眠、替代混乱，仅影响对手战斗场；回合间正反面均覆盖，唯一硬币来自睡眠检查。
7. 实际迷雾能量与不眠特性阻止睡眠，但不阻止 40 点伤害。
8. 正常鬼斯→鬼斯通进化、进化当回合攻击和旧招式效果不残留。
9. 真实作者 Host + A3 外部决策口 + `HeadlessMatchBridge`，三个招式各两个座位，共 6 个 MAIN 窗口：公开投影、当前索引提交、引擎执行和旧窗口重复提交拒绝均通过；每场 1 次 policy success、1 次 engine commit，错误、非法输出、fallback 和拒绝计数均为 0。冻结 Competitive 公共 frame 校验同时通过。这两张卡本身没有需要玩家选择的 UCIS 子窗口。

修复前 `red/report.json` 为 3 passed / 6 failed，明确复现抽牌缺失、睡眠缺失和真实卡注册缺失。最初测试夹具另有两处前置条件不完整：Host 使用了空场景；临时放入手牌的进化卡未完成正常开局的全牌组注册。补齐正式 headless 场景和进化牌注册后通过。这两个夹具问题不计为产品缺陷，也不声称 Host 曾因此漏掉合法招式。
