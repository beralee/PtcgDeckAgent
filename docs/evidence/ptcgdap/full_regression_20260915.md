## 已定位并修复的问题

- 完整本机卡牌目录在每次完整性检查时反复慢速序列化：为已经验证的相同二进制载荷增加编译时指纹快速路径；载荷变化仍执行原完整校验。篡改、重算伪造指纹和大小限制测试保留。
- Python JCS 字符串序列化性能退化：保留 I-JSON 检查、数字和 UTF-16 键排序，使用 C 实现字符串转义；追加输出一致与耗时回归。
- 启动日志中的 NUL 警告来自模型特征哈希域：Godot 将字符串里的 NUL 替换成 U+FFFD，导致 UID 特征和选项语义哈希与 Python 合同不一致。改为逐段写入 ASCII 与二进制零字节。独立 SHA256/Python 对照用例先红后绿，两个 UID 与一个语义哈希精确一致，原生推理、模型包预检和真实对局另做集成复测。
- 历史策略包及来源印刷被当前内容更新移除，导致冻结合同测试找不到精确输入：从公开 Git 历史恢复对应字节到测试夹具，记录来源和 SHA256，冻结身份约束不变。实际玩家目录仍只扫描现有本机策略。
- 设备执行清单未跟随真实执行入口更新：重新生成本机 executor/device 清单及关联指纹，保留开发用途和禁止扩大发布权限的校验。
- 基础特性查询在不完整场景上越界；投币测试替身没有调用父构造时缺少随机上下文；目录效果审计缺少生产环境的 EffectProcessor 绑定。分别修复拥有层或测试场景。
- 后续完整运行暴露灼伤/睡眠偶发断言失败：旧确定性投币替身只覆写 `flip()`，元数据及成组投币绕过预设值使用真随机数。对所有同类替身补齐元数据入口，不改变生产随机数接口；新增禁止逃逸到随机端口的明确反例，先红后绿。相关 47 个套件按功能/AI 分组复测。
- 新卡的交互步骤未统一进入 UCIS 编译器，补齐方法接入并重新生成本机交互登记。
- 巢穴球、友好宝芬、高级球的空检索结算仍只接受旧字符串，拒绝界面给出的布尔选择。补齐校验并保留非法值拒绝回归。
- 光辉胡地数量选择升级为 NUMBER 对象后，经典策略仍强制将整个对象转成整数。改为读取当前选项中的数量并返回原选项。
- N 索策略未为普通印刷招式计算可攻击预测，导致已经满足能量的基础宝可梦仍被判定无法攻击。补上按规则校验能量的印刷招式预测。
- 自爆恶喷训练题读取了后来更新的玩家卡组，十道题卡池不足。训练状态工厂读取对应的公开冻结卡组，60 张守恒验证不变。
- 对战设置卡组弹层使用外部窗口而非自身布局区域计算尺寸，造成嵌入/短窗口溢出。改为自身实际布局尺寸。
- 将训练帮助/退出等方法抽到独立拥有层以满足主对战脚本规模门禁后，训练帮助的旧源码位置断言失效；改为调用真实场景入口，验证关卡说明恰好打开一次且不会打开宙斯选牌器。
- Web 原生输入框被 Godot 隐藏 IME 定时抢焦点，随后误触发失焦删除。真实 DOM 编辑期间仅将引擎隐藏输入节点设为不可聚焦，关闭时恢复，浏览器原生输入和组合输入仍由 DOM 处理。
- Web 测试默认动作缺少较短超时，补充动作和桥接请求超时及长循环进度。基准比赛输出每场进度，避免把连续计算误当作卡死。
- iOS 粘贴保存测试原先点击屏幕外的保存按钮，不能检验保存功能；现在先通过画布触摸事件滚动按钮到屏幕内再点击，并从配置文件重新读取验证合成测试密钥。取消、剪贴板拒绝和一键读取路径保留。
- D 盘空间不足导致 Web PCK 写入失败：支持独立导出和测试产物目录，本次移至 C 盘临时目录；旧测试产物移动保留，没有删除玩家数据。
- 新增 30THC 图片为 PNG，但种子约定使用 WebP：逐张无损转换并验证解码后的 RGBA 字节完全一致，刷新种子内容指纹。清除清单中不存在的测试图片引用。
- 其余过期断言更新到当前交互语义：神奇糖果的卡牌/目标成对选择、乌栗布尔分支、可选重抽数量、引擎持有的提示归属，以及已实现英文印刷不应被仅凭 LEN_ 前缀认定为占位卡。
