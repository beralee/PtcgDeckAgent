## 机制与错误

运行能力来自已经过完整性和签名检查的 `policy/adapter.json`，不是文件名、策略名称
或作者宣称的版本。`AuthorStrategyRuntimeCompatibility` 登记 profile 首次支持版本，
导入器保留结构化要求，安装器向界面传递诊断，策略详情显示最低客户端版本。
旧策略未声明新增 profile 时不新增最低要求，也不改变其历史 metadata 形状。

- `package_runtime_upgrade_required`：已知 profile，但当前能力集合不包含它。
  提示当前版本、最低版本/build，以及更新后重启再导入。
- `package_runtime_profile_unknown`：未知或错误类型的 profile，拒绝导入，明确无法确定最低版本。
- `package_policy_unsupported`：其余策略规则校验失败，保留稳定错误码并提示检查策略与客户端兼容性。

### 已导入但暂不可开战

导入校验和开战许可是两个检查。此前遗漏了这两份原包的本地开发登记，
因此格式修好后仍返回 `development_candidate_not_authorized`，界面又隐藏了原因。
现将上述精确 ID、版本、摘要和用户导入来源登记为 Windows 本地开发策略；
0.29 为 393 条适配规则，0.23 为 404 条，两包均为 675701 的 60 张、27 种印刷。
其他版本、改动字节、其他导入来源和未验收平台仍然拒绝，开发签名不提升为生产信任。

实际点击开战还会异步准备包。原准备目录错误地把全部元数据当成市场已就绪记录，
导致开发包再次被 `control_distributed_package_not_ready` 拦截；现分别保留元数据
与实际已就绪记录，开发和市场包各自重走原有完整资格检查。

列表、详情和 AI 选择页显示具体拒绝原因；导入成功但不能开战时立即说明，
未知原因保留错误码，不能仅显示“暂不可开战”。已安装的原包不必重新导入：
完全退出运行中的游戏，再从包含此修复的本地 0.6.3 工程启动即可。
先前启动的 0.6.3 进程或旧导出 EXE 不会因磁盘源码变更自动具备此修复。

新能力包括受审换目标伤害预测、公开攻击入口和资源连续性规划。
规则使用显式 profile 启用，Base 的 mandatory/terminal、hard tier 和 veto 仍有最终权力。
保留游戏自身的 Turn Program 和后排伤害扩展，未用旧研究解释器整库覆盖游戏。
合同由游戏原有生成器重新生成，内置目录缓存同步刷新；不手改合同摘要。

## 验收与边界

原 0.29 在修改前原生导入失败；修改后原 0.29、0.23 均通过原生导入。
0.29 的 190 个冻结原生用例逐项匹配历史预期，覆盖负例与选项重排。

导入及安装仍执行原签名、牌表、完整性和执行资格检查，不把开发签名提升为生产信任。

本次不声明新整局胜率、CABT parity、Android/macOS 设备验收或生产发行。
复现证据和逐文件修改前快照位于 Forge 的 `work/dragapult-client-compat-20261003/`。
回退时仅回退本任务列出的文件增量，不回滚整个脏工作树；0.29 包保持原摘要可供复验。

开战修复的专项 RED→GREEN、异步与目录回归、源码增量和回退快照另存于
Forge `work/dragapult-local-start-20261003/`。0.29 原包经真实安装、异步句柄、
