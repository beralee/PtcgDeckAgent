## Ambiguities, Conflicts, and Assumptions

| Topic | Issue | Blocking? | Assumption / decision |
|---|---|---:|---|
| `docs/design.md` | Requested by the goal but missing from repo. | No | Use `docs/superpowers/specs/2026-07-11-full-card-catalog-on-demand-images-design.md` as source of truth. |
| Truly complete official card corpus | The generated snapshot now proves the catalog-only path with CSV4C/015, but still contains only 449 cards rather than every official card. There is no checked-in all-card ingestion snapshot. | Yes for the original “all cards” product claim | Keep the architecture and CSV4C/015 reference path; next build an authoritative bulk importer and publish a complete snapshot before claiming full-card coverage. |
| Remote catalog patch in MVP | The spec recommends bundled catalog first and remote patch second phase, but the goal says implement completely. | No | Implement a local remote-cache fallback path and manifest verification hooks where feasible; live server publishing remains a deployment follow-up. |
| "All card display entrances" migration | The spec says gradually migrate all display entrances to `CardImageOrProxyView`, including battle, HUD, poster. | No | Reuse existing `BattleCardView` for battle where it already provides local-only proxy behavior, and create shared helper/component for non-battle views. |
| Android mobile-network detection | Godot project does not appear to have a robust network-type API wrapper. | No | Default Android policy is conservative queue/concurrency; explicit metered-network detection is documented/manual unless a local API exists. |
| i18n | Project uses `locale/default="zh_CN"` with mostly hardcoded Chinese strings; no separate i18n table was found. | No | Follow existing hardcoded Chinese UI style; avoid introducing a new i18n system in this feature. |
| Package slimming | Removing packaged card images is a release packaging decision and may break existing tests expecting bundled fallback images. | No | Preserve compatibility now; package trimming will be marked as release-step follow-up unless explicitly safe after test updates. |
