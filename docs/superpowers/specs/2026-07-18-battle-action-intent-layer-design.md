# 对战交互意图层设计

## 范围

本次只实现对战中的交互意图表达，不增加卡牌素材，也不改变任何规则、结算顺序或输入权限。

- 空闲时保持战斗区干净；模型仍计算手牌、宝可梦和竞技场合法性，但不主动发光或显示可用动作文字。
- 选择能量、道具、进化或基础宝可梦后，只用轻量目标轮廓和细路径表达合法目标；路径从来源卡牌实际可见卡面的正中心开始，不绘制来源灰框，也不在目标上叠加“可选择”等中文。
- 非法尝试使用靠近来源或目标的非模态原因提示；提示约 2.5 秒自动淡出，下一次点击或成功操作立即收起。
- 不包含伤害/战果预演、操作复盘、额外回合资源栏或自动替玩家执行动作。

## 约束

- 意图模型是规则状态的只读投影，全部合法性来自现有 `RuleValidator`、`EffectProcessor` 与 `GameStateMachine`。
- 不复制或近似实现规则；目标集合必须由现有验证器逐目标计算。
- 只展示当前视角玩家可见的信息，不扫描对手手牌、牌库或奖赏卡。
- 覆盖层 `mouse_filter` 固定为 `IGNORE`，不能抢占鼠标、触摸或手势。
- 进入回顾、效果选取、AI 暂停、抽牌展示或非己方主要阶段时清空提示。
- 横屏与竖屏共享同一模型；提示框根据当前画布边界钳制，不能越出屏幕。
- 手牌来源、场上目标和换位动画统一把控件四角投影到覆盖层坐标，不能用全局矩形位置相减近似处理缩放、旋转或重挂载布局。

## TDD 验收

1. 模型能识别可用物品，并为已使用支援者和已手贴能量保留具体禁用原因，但空闲覆盖层不绘制常驻入口。
2. 选中能量只生成己方已占用宝可梦槽位目标，不出现空槽或对手目标。
3. 进化与基础宝可梦生成精确目标集合，并遵守动态备战区上限。
4. 模型继续识别可用特性、招式和撤退，覆盖层不为这些动作绘制发光、蓄力或文字提示。
5. 竖屏覆盖层不拦截输入、细路径数与目标数一致、目标文字数为零；变换画布中的来源和目标坐标与真实卡牌一致，且意图计算前后规则快照一致。
6. 就地失败提示完整位于屏幕内，显示具体原因，并可自动淡出、响应下一次操作或随控制器清理。
