# 对战交互 VFX 全量设计

## 目标

在现有对战交互意图层上增加一套完全程序化的视觉反馈。所有效果只表达“哪里可操作、当前指向哪里、操作是否成功、为什么失败”，不改变规则、不代替输入、不延迟引擎结算，也不依赖新增图片素材。

## 不可破坏的边界

- VFX 覆盖层固定使用 `MOUSE_FILTER_IGNORE`，不能接管鼠标、触摸、拖动或手势。
- 规则状态只由 `GameStateMachine`、`RuleValidator` 与 `EffectProcessor` 修改；VFX 只能读取结果。
- 所有瞬时效果有明确最长时长并自动回收，不加入现有阻塞式动画队列。
- 视觉上的浮起、磁吸、回弹和抖动只绘制在覆盖层，不移动真实卡牌控件和命中区域。
- 回顾模式、交互选择、抽牌展示、AI 等待和非己方主要阶段不显示可执行意图。
- 对手隐藏区域永不参与特效推导。
- 横竖屏统一从控件的最终屏幕变换投影四角或中心，再转换到对应动画宿主的本地坐标；引导线、强制换位、跨区域飞牌、抽牌/奖赏交换、攻击和待命特效必须匹配真实卡牌位置，气泡、波纹和扫光必须钳制在可见画布内。

## Godot 实现方式

采用一个常驻 `Control`/`CanvasItem` 程序化渲染器，通过 `_draw()`、贝塞尔曲线、时间参数、`Tween` 和局部事件队列绘制。这样能够共享 Godot 的画布变换与移动端批处理，同时避免为粒子创建大量独立输入节点。

## 效果清单与触发

| 效果 ID | 表现 | 触发 | 功能隔离 |
| --- | --- | --- | --- |
| `legal_target_glow` | 选中卡牌后的合法目标轻量描边 | 进入目标选择 | 只读，不绘制文字 |
| `attribute_action_glow` | 已停用空闲态属性发光 | — | 保留效果 ID 兼容性 |
| `flow_path` | 来源到目标的细线、微光点贝塞尔路径 | 选中需指定目标的手牌 | 线宽不超过 2px |
| `multi_target_fanout` | 多条路径按索引错峰展开 | 合法目标多于一个 | 只读 |
| `success_converge` | 路径向目标收束并爆发确认环 | 引擎动作返回成功 | 成功后触发 |
| `invalid_recoil` | 局部红橙回弹残影、冲击波和原因气泡 | 引擎拒绝动作 | 不阻塞 |
| `touch_ripple` | 点击位置扩散波纹 | 已被原输入流程接受的点击 | 不参与命中测试 |
| `energy_orbit` | 能量沿弧线汇入并绕目标旋转 | 附着能量成功 | 成功后触发 |
| `tool_lock` | 四段机械锁环向目标闭合 | 附着道具成功 | 成功后触发 |
| `retreat_swap` | 战斗位和备战位双向弧线交换 | 检测到真实场区交换 | 基于前后快照 |
| `ability_ripple` | 从宝可梦中心扩散属性色涟漪 | 特性成功 | 成功后触发 |
| `attack_ready` | 已停用空闲态招式蓄力提示 | — | 保留效果 ID 兼容性 |
| `phase_sweep` | 进入主要阶段时从手牌扫向场区 | 阶段转换为 MAIN | 不延迟回合 |
| `low_hp_pulse` | HP 危险宝可梦整张卡牌周边低频红框 | 剩余 HP 不高于 30% | 不覆盖卡面文字 |
| `combo_cadence` | 连续成功操作的确认环逐步增强 | 短时间连续成功动作 | 仅视觉计数 |

## 属性颜色

火、水、雷、草、超、恶、斗、钢、龙和无色使用稳定色表。颜色只影响亮光，不覆盖卡图，也不作为规则类型判断依据。

## 节奏与可访问性

- 空闲态不绘制可用手牌、宝可梦、竞技场、特性、招式或撤退的常驻提示。
- 点击波纹 0.3 秒，成功效果 0.55–0.9 秒，失败反馈 0.45 秒，阶段扫光不超过 0.8 秒。
- 同时存在的瞬时事件有硬上限，超出时优先回收最旧事件。
- 低血量提示只沿整张卡牌周边绘制；连续操作等级有上限并在超时后重置。
- 后续可直接将动画强度接入“减少动态效果”设置，而不改变事件契约。

## TDD 验收

1. 注册表完整包含全部 15 类保留效果；已移除灰色来源磁吸框 `source_magnet` 和进化后紫色横线 `evolution_ladder`。
2. 空闲提示数量为零；细路径从可见卡面正中心开始，多目标展开和整卡周边低血量提示可被快照检查。
3. 所有瞬时事件有界、自动过期，并且覆盖层永不接管输入。
4. 控制器从真实状态推导目标与低血量提示，不绘制空闲属性/攻击入口，前后规则快照完全一致。
5. 附能、进化、道具、特性、触摸、阶段、交换和失败均映射到正确效果，成功动作同时更新节奏反馈。
6. 通过既有对战 UI、横竖屏、触摸、视觉运行时和场景生命周期回归。
7. 缩放、旋转和嵌套父节点下，引导线、强制换位、飞牌、抽牌/奖赏交换、攻击及待命特效的屏幕中心必须与真实来源和目标一致；动画节点加入最终宿主并完成布局后才允许测量尺寸和计算起止位置。
8. 手牌引导锚点使用手牌区实际可见的设计尺寸，不能使用被滚动容器裁切后的膨胀内容高度；宝可梦特性反馈优先使用槽位运行时 ID，并限定在行动玩家一侧，不能仅凭同名卡搜索。
