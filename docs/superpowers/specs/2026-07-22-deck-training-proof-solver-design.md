# 卡组训练残局证明器设计

日期：2026-07-22  
状态：第一版核心与生产引擎适配已实现

## 1. 目标

证明器用于离线判断一个残局是否存在可强制达成的解，并验证对手采用最佳防守时该解仍然成立。它不参与玩家对局中的操作判定，也不向玩家强制作者路线。

核心原则是“证明失败要保守”：只允许 `PROVEN`（已证明）、`REFUTED`（已反证）、`INCONCLUSIVE`（尚未证明）三种结果。交互未枚举、随机结果未枚举、循环无进展或搜索预算耗尽都必须返回 `INCONCLUSIVE`，不能把一次 AI 获胜当成证明。

## 2. AND/OR 求解模型

- 玩家节点是 OR：存在至少一个合法选择能强制达成目标，节点才可证明。
- 对手节点是 AND：全部合法防守之后玩家仍能达成目标，节点才可证明。
- 随机节点也是 AND：精算题默认要求所有结果都成立。固定牌序属于场景定义，并进入场景指纹。
- 终局叶子直接使用训练目标计算结果，不使用局面估值或胜率近似。
- 状态键用于换位表；当前递归路径再次遇到相同状态且没有进展时，返回 `INCONCLUSIVE`。

对手节点的证明树保留所有防守分支，主变化选择使玩家解法最长的分支，作为“最佳防守”展示。玩家节点可统计所有必胜首着；发布门要求根关键选择唯一，且任何未知分支都会使唯一性变成尚未证明。

## 3. 生产规则适配

`DeckTrainingEngineProofAdapter` 从 `DeckTrainingStateFactory` 创建的真实 `GameStateMachine` 开始：

1. 用 `AILegalActionBuilder` 枚举正式合法动作。
2. 用 `GameStateCloner` 为每条分支创建隔离状态。
3. 将动作序列化为卡牌实例 ID、槽位顶层卡 ID、攻击/特性编号和目标引用，保证克隆后可重放。
4. 通过正式 `AIOpponent`/`GameStateMachine` 动作入口执行，而不是在证明器内复刻卡牌效果。
5. 用训练目标评估器计算奖赏或指定击倒进度，并按己方完成回合数执行期限。

第一版已经支持普通主阶段动作和回合交接。需要目标选择的卡牌效果，以及击倒后的拿奖/派出等提示，尚未做合法选项穷举；适配器会明确返回 `INCONCLUSIVE`。后续只能通过逐类增加完整交互枚举器扩大可证明范围，不能用规则 AI 的单一选择替代穷举。

## 4. 证明证书

每次搜索输出 JSON 证书，包含：

- 求解器版本、生产适配器名称、场景 SHA-256 指纹；
- 状态、失败或未决原因；
- 根节点是否唯一解、最短玩家操作数和主变化；
- 全部根分支、对手最佳防守、失败原因和完整证明树；
- 对手防守是否穷尽、所有未支持分支原因；
- 访问节点、换位表命中、终局/未决叶子、耗时和预算退出原因。

场景指纹覆盖场面、双方牌区、固定牌序、回合标记与目标。修改任何相关数据都会使旧证书失效。

## 5. 发布准入

`DeckTrainingAdmissionVerifier.verify_for_solver_promotion` 同时检查作者合同和证明证书。只有以下条件全部满足才能进入“已证明”题库：

- 作者合同通过；
- 状态为 `PROVEN`；
- 求解器版本和场景指纹一致；
- 对手与随机分支穷尽，没有未支持分支；
- 根关键选择唯一；
- 最短路线至少包含 5 个玩家操作；
- 搜索没有耗尽深度、节点或时间预算。

现有 70 题仍属于作者合同题库，不会因为新增接口而被虚假标记为已证明。它们应逐题补齐效果交互枚举后生成证书，再迁入严格发布集合。

## 7. 验收覆盖

- 一个含诱饵首着和两个最佳防守分支的完整图，只允许唯一的五操作路线通过。
- 未支持交互可能隐藏第二条解时，唯一解必须判为 `INCONCLUSIVE`。
- 修改场景目标后，旧证书必须因指纹不一致被拒绝。
- 生产适配器必须从真实合法动作中生成稳定唯一 ID，并通过正式状态机完成回合交接。
