# V18CPG 多信息纪元决策—执行闭环改造设计与行动计划

日期：2026-07-25
架构：V18 Conditional Policy Graph（V18CPG）
适用范围：全部 24 套内置 18.0 LLM 卡组
不在范围：旧版 `DeckStrategy*LLM`、旧决策树运行时、Agent/完整智能体分支、Rule 策略本身

## 1. 结论

本次问题不是“猛雷鼓不懂猫头夜鹰”，而是宿主、策略和交互执行之间缺少一个强类型的信息纪元协议。

PTCG 的一个主阶段并不是一次静态决策，而是一串交替发生的过程：

1. 根据当前公开信息选择动作；
2. 执行动作并进入搜索、抽牌、展示牌库、交换、弃牌取回等交互；
3. 交互完成后获得新的公开信息；
4. 旧策略图若有合法且已验证的条件分支则本地续跑，否则针对差异重新规划；
5. 重复上述过程，直到攻击或明确结束回合。

因此，基础架构必须同时支持两种能力：

- **前瞻图**：模型一次返回当前动作、确定性的多动作前缀和信息检查点，客户端能在命中条件分支时零调用续跑。
- **信息纪元重规划**：任何成功动作/交互一旦产生此前不可见且会改变合法动作或价值排序的信息，就结束旧纪元；若图中没有可证明安全的分支，立即以紧凑差异请求重新规划。

模型调用次数不能按“每回合一次”硬限制，也不能在每个微交互后无条件重问。正确的硬约束是：**每个公开信息纪元最多一个同版本在途请求；同一公开状态不重复请求；有可验证本地分支就不请求；新信息可连续产生多个新纪元。**

## 2. 已确认的生产故障

生产日志中的猫头夜鹰案例已经证明：

- 第一次根请求约 2.33 秒完成并选择进化猫头夜鹰；
- 猫头夜鹰交互完成、训练家卡加入手牌后，第二次请求在约 151 毫秒内正确启动；
- 第二次请求约 2.48 秒后返回并选择了大地容器/古代支援者方向；
- 但宿主在第二次请求启动的同一执行步把 `pending` 当成“没有进展”，触发通用 `no_progress` 回合结束；
- 因而模型实际已经二次思考，结果却没有机会进入执行层。

根因包含三层：

1. `AIOpponent.run_single_step()` 用 `false` 同时表达“真正无动作”和“异步策略正在等待”。
2. 对战宿主在调用前检查等待状态，但请求是在调用内部才启动，存在必现的检查—使用时序窗口。
3. 主动作结果有审计记录，效果交互完成却没有 V18CPG 专属、公开信息安全、可关联动作所有权的事件桥；非信息路由触发的信息能力可能漏掉纪元重开。

另一个抑制上限的约束是：已发布卡组每回合第一次强制模型判断把 `max_policy_nodes` 压成 1。这会阻止模型返回“动作 → 信息检查点 → 条件分支”的完整图，与 CPG 的设计目标相冲突。

## 3. 设计目标

### 3.1 功能目标

- 连续使用猫头夜鹰、大地容器、支援者抽牌等多次滤牌时，每次新信息都能被消费。
- 模型等待绝不被宿主解释为无进展或结束回合。
- 交互完成后，执行层必须形成可审计的“动作结果 → 信息事件 → 分支/重规划 → 后续动作”链。
- 所有 24 套卡组都通过同一个 V18CPG 基类获得能力；卡组 profile 只描述策略语义，不重复实现生命周期。
- Rule 仍是精确失败下限；网络、超时、JSON、图校验失败不改变 Rule 决策语义。

### 3.2 性能目标

- 可命中的策略图分支继续零模型调用。
- 差异请求只携带公开状态差异、当前候选和剩余策略上下文。
- 不增加轮询式模型调用，不对相同 `observation_hash` 重复请求。
- 同一个 `(turn, observation_version, decision_window)` 最多一个在途请求；过期响应丢弃。
- 延续现有可见等待预算、截止时间和本地回退机制。

### 3.3 安全目标

- 事件桥只读取双方公开区域、己方手牌、数量信息及引擎公开交互元数据。
- 不暴露己方牌库身份/顺序、奖赏卡身份、未展示的对手手牌。
- 不引入随机数，不改变洗牌、硬币或同种动作的稳定排序。
- 不改旧 LLM、Agent 和 Rule 策略实现。

## 4. 核心协议

### 4.1 宿主执行步的三态返回

`run_single_step_result()` 返回：

| 状态 | 含义 | 宿主行为 |
|---|---|---|
| `progressed` | 已执行动作或解决交互 | 计入动作数并继续调度 |
| `waiting_policy` | V18CPG 已启动/保有在途请求 | 显示等待，不计动作，不结束回合 |
| `no_progress` | 当前没有执行且没有 V18CPG 在途请求 | 才允许进入现有通用兜底 |

旧 `run_single_step() -> bool` 保留，供旧运行时和无头工具继续使用。三态方法是兼容包装，不改变旧语义。

关键不变量：

> `waiting_policy` 永远不是终局信号；只有 `no_progress` 才能进入宿主原有结束回合判定。

### 4.2 V18CPG 公开状态快照

观察网关增加不递增模型观察版本的 `snapshot_public_state()`，包含：

- 回合、当前玩家、阶段、一次性配额；
- 己方公开手牌身份、弃牌、放逐区、场面、牌库/奖赏数量；
- 对手公开弃牌、放逐区、场面、手牌/牌库/奖赏数量；
- 竞技场；
- 去除瞬时版本后的稳定公开哈希。

快照明确不包含：

- 己方牌库卡牌身份或顺序；
- 双方奖赏卡身份；
- 未展示的对手手牌身份；
- 效果交互中不属于 `visible_scope` 的候选。

### 4.3 动作—交互事件桥

新增 `V18CPGEventBridge`，比较动作/交互前后公开快照并生成：

```text
resolution_id
sequence
event_type
step_kind
success
interaction_complete
information_material
before_hash / after_hash
public_delta
acquired_own_hand_cards
released_own_hand_cards
```

`information_material=true` 的条件至少包括：

- 己方手牌出现新身份；
- 己方牌库数量变化且动作/交互成功；
- 合法动作依赖的公开场面、弃牌、放逐区或配额发生变化；
- 完成具有公开可见范围的牌库/手牌展示交互；
- 交互元数据明确标记为信息检查点。

事件桥只描述“发生了什么”，不做策略选择。其 `resolution_id` 由单调序列和公开哈希构成，不使用 RNG。

### 4.4 信息纪元所有权

主动作记录保留原决策所有权：

- `policy_graph_branch`
- `model_selected_local_route`
- `local_gate`
- `deadline_fallback`
- `schema_fallback`
- `rules_fallback`

交互事件不覆盖主动作所有权，而是附着到尚未消费的动作结果。这样猫头夜鹰即使最初被归类为 `route:evolve`，其进化触发的搜牌交互也能把该动作升级为 `information_event=true`。

纪元重开规则：

- 本地/超时/协议回退选择一旦成功产生信息事件，旧本地根必定失效并重开。
- 模型图拥有有效类型化检查点或执行游标时，优先本地推进；无法覆盖新事实才差异重规划。
- 模型图若执行了普通路由但随后产生未声明的信息交互，也必须重规划，不能因原路由名不是 `route:information` 而忽略新牌。
- 失败动作不产生新信息纪元，除非失败本身改变了公开状态（此时由公开差异证明）。

### 4.5 前瞻图与多次思考的边界

首次请求恢复 profile 的图节点上限（默认 8、硬上限 12），不再强制 1 节点。

模型提示约束：

- 简单、无后续信息的决策仍默认单节点。
- 预计会打开抽牌、搜索、完整牌库选择或多动作交互的根动作，属于“确有必要的未来条件分支”。
- 在节点预算允许时，应返回“精确根动作 → checkpoint → 条件 follow_route / otherwise=replan”。
- 对确定性的 2–4 步动作可用 typed route，由执行游标本地续跑。
- 信息动作不能被错误地塞在原子宏中间；新信息后必须经过 checkpoint。

这形成分层决策：

1. 当前明确动作：精确 candidate；
2. 可预测短序列：typed route；
3. 信息分叉：checkpoint；
4. 图未覆盖的新信息：紧凑 delta replan；
5. 网络/协议失败：精确 Rule floor。

## 5. 24 套卡组的继承契约

全部 24 个 profile 必须实例化同一个 `V18ConditionalPolicyStrategy`，并自动具备：

- 三态宿主等待协议；
- 公开状态快照；
- 事件桥；
- 信息纪元重开；
- 策略图/执行游标优先；
- 差异重规划；
- 可见等待预算；
- 过期响应丢弃；
- 精确 Rule floor。

卡组只允许在 profile/module 层声明：

- 哪些 route、语义角色和资源受保护；
- 哪些搜索组合具有配对约束；
- 哪些公开事实可形成确定性证书；
- 交互选择的排序规则。

禁止每套卡组复制事件桥、请求生命周期或宿主等待代码。若某卡组需要特殊信息能力，应扩展共享的语义/能力模块并带跨卡组回归，不在卡组 wrapper 中写流程补丁。

## 6. TDD 测试矩阵

### 6.1 红灯：宿主时序

1. V18 策略在 `run_single_step()` 内启动请求。
2. 返回必须是 `waiting_policy`，不能是 `no_progress`。
3. 等待不计动作、不执行结束回合。
4. 响应就绪后下一步必须真正执行所选动作。
5. 连续重复三轮，证明不是单次偶然。

### 6.2 红灯：连续信息事件

构造公开状态链：

1. 猫头夜鹰搜索后：手牌新增训练家；
2. 大地容器后：手牌身份再次变化、牌库下降；
3. 支援者抽牌后：手牌再次新增、牌库再次下降。

逐段断言：

- 三个唯一 `resolution_id`；
- 三次 `information_material=true`；
- 每次新获得卡牌身份被准确记录；
- 每段都形成新的公开哈希；
- 失败且无状态变化的步骤不误报信息。

### 6.3 红灯：决策—执行收益

执行级夹具必须记录并断言：

```text
request_started
waiting_policy
response_ready
action_executed
interaction_resolved
information_epoch_reopened 或 graph_branch
next_action_executed
```

收益指标不是“多发了请求”，而是：

- 新获得的可用牌在同回合后续动作中被执行；
- 未发生误结束回合；
- 对照旧二态行为，后续动作数从 0 提升到至少 1；
- 三次滤牌链中每段都有决策消费者。

### 6.4 红灯：24 套继承

遍历 `ALL_DECK_IDS`：

- 24/24 都由统一策略类构造；
- 24/24 的运行时元数据为 `v18_conditional_policy`；
- 24/24 对普通 route 附带的 `information_event` 都会按共享规则重开本地纪元；
- 24/24 不需要卡组专属事件方法；
- 24/24 保持各自精确 Rule profile 绑定。

### 6.5 红灯：隐藏信息防火墙

在己方牌库、己方奖赏和对手手牌放入唯一哨兵 UID，断言公开快照、事件和审计 JSON 均不含哨兵；将同一对手手牌放入明确的展示交互时，只能通过既有 observation 的 `visible_scope` 通道出现，事件桥本身不扩大可见范围。

## 10. 实施结果（2026-07-25）

本设计已经按 TDD 落地，不再只是方案。

### 10.1 已实现

- `AIOpponent` 保留旧布尔接口，并新增 `progressed / waiting_policy / no_progress` 三态执行接口。
- 对战宿主在执行步内部新建模型请求时会进入等待，不再触发 `ai_step_no_progress_fallback`。
- 观察网关新增不消耗模型 observation version 的公开状态快照。
- 新增共享 `V18CPGEventBridge`，覆盖主动作、效果交互、连续搜牌/抽牌和完整牌库空选。
- V18 基类把信息事件附着到原动作所有权，并把新获得的公开手牌身份写入紧凑 delta。
- 本地根在信息事件后强制结束旧纪元；模型图先尝试类型化 checkpoint，未覆盖则差异重规划。
- 已发布卡组首个主阶段模型请求恢复 profile 图节点预算，不再强制单节点。
- prompt 明确要求预期会打开抽牌/搜牌信息窗口的根连接 checkpoint 和 `otherwise=replan`。
- 24 个 profile 全部继承同一个基类实现，没有增加猛雷鼓或其他单卡组流程补丁。
