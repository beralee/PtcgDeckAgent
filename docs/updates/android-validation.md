# Android 更新验证版

本地成品位于 `output/android-update-lab/`。手机只需安装 **Install-A-first.apk**，桌面名称为 **升级验证**。它使用独立包名 `cn.skillserver.ptcg.updatelab`，不会覆盖正式游戏，也无需修改服务器、上传文件或修改在线版本清单。

## 手机快速验证

1. 将 `Install-A-first.apk` 传到 Android 手机并安装，打开“升级验证”。初始版本是 A（1.0.0）。
2. 先选择异常场景，观察提示并尝试取消、重新下载。点“重置本次测试”可换场景。
3. 最后选择“正常更新 → 安装 B 版”。下载、校验完成后点“安装更新”。首次安装需要在 Android 系统页面允许此来源安装应用，返回后确认系统更新提示。
4. 更新后重新打开“升级验证”，应显示 **B 版 ✓**，数据保留标记仍为 **created-in-1.0.0**。
5. 再次从头验证时，只卸载“升级验证”并重新安装 A。不要卸载正式游戏。

A 已内置 B 的完整 APK，不需要另装 `B-update-payload.apk`，无需连接线上服务。支持 Android 7.0 及以上，A 约 214 MiB，较大是因为包含测试所需的第二个安装包。默认通过真实的本机 HTTP 连接交给 Android 系统下载，不依赖虚假的下载进度；设备需要启用网络，让系统允许开始下载。第一次下载请允许更新通知。

**重点验证“关闭应用继续下载”时，请使用下面的电脑局域网服务。** 内置服务与验证应用在同一个进程，关闭应用也会关闭这个临时服务器；正式游戏的更新服务器没有这个限制。无需更新任何线上服务。

Android 仍会要求系统安装确认；不会静默绕过权限或系统安装界面。拒绝权限、取消系统确认后，应能回到应用继续重试。

## 场景与预期

| 场景 | 操作与预期 |
| --- | --- |
| 正常更新 | 完整下载、大小和 SHA-256 校验，通过系统确认覆盖安装 B，保留数据标记 |
| 慢速下载 | 关闭弹窗后底部仍显示百分比、大小和速度，点击回到详情；通知栏展开下载通知后可见系统进度条 |
| 下载一半断开 | 交由系统重试；不能恢复的任务提示重新下载，半包不能安装 |
| 连接无响应 | 服务器只发响应头，不发文件；由 Android 系统管理超时和重试，界面仍能取消下载，不使用旧的 5 秒应用超时 |
| 不完整文件 | HTTP 正常结束但包大小不符，阻止安装 |
| 文件损坏 | 大小正确但 SHA-256 不符，阻止安装 |
| 不是 APK | 文件本身的大小、校验均正确；点击安装后由原生包解析拒绝，清掉不可安装包，提供重新下载和官网入口 |
| 地址失效 | 返回 404，提示重试，不把错误响应当安装包 |
| 空间不足 | 注入低可用空间，不实际填满手机；开始前阻止下载并说明原因 |
| 缓存被清理 | 下载完成后测试自动移除本地包；点击安装应发现文件缺失并要求重新下载 |
| 版本不符 | 清单要求 build 3，但真实包为 build 2；原生校验拒绝安装 |
| 关闭应用 | 使用电脑服务慢速下载，切桌面、划掉应用后观察通知进度继续增长；重新打开接回同一任务 |
| 关闭后下载完成 | 使用电脑服务，下载时关闭应用；完成通知点开后进入游戏校验，之后才允许安装 |
| 关闭通知权限 | 下载不会崩溃或丢失；弹窗出现“开启更新通知”，游戏内进度入口仍可用 |
| 拒绝安装权限 | 安装时返回且不授权；保留完整包，提供重试 |
| 取消系统安装 | 系统确认页面取消；保留当前 A 版和完整包，允许再次安装 |

Android 下载归系统管理，游戏进程退出不会主动取消任务。断网后系统等待并重试，服务器提供 Range/ETag 时可续传；附带电脑服务已支持这两项。只有玩家明确取消、重置测试或重新下载时才移除旧任务。系统设置中的“强行停止”、省电和厂商后台限制仍由 Android 决定，不能与普通退出等同。

## 验证退出应用与真实 Wi-Fi 中断

默认本机服务不受飞行模式影响。如需测试真实网络断开：

1. 在电脑上打开输出目录，运行 `start-lan.ps1`（电脑需要 Python，仅测试工具需要，手机不需要）。
2. 手机和电脑连接同一局域网。将工具显示的 `http://192.168.…:18761` 地址填到验证应用底部输入框；不要使用电脑的 `127.0.0.1`。
3. 选择慢速下载，点“后台下载”。游戏底部应显示持续更新的进度；切到桌面并划掉应用，在通知栏展开下载通知，进度应继续增长。再打开游戏应接回原任务。
4. 可另测关闭手机 Wi-Fi（同时关闭移动数据），游戏提示等待网络；恢复网络后系统继续。保持电脑服务运行。
5. 最后选择正常更新，下载时关闭应用。完成后应收到“更新包已下载”，点通知返回游戏校验，然后确认安装 B。
6. 测试结束在电脑按 Ctrl+C 停止服务。Windows 若提示防火墙访问，只需按实际网络选择私人网络。

附带服务只提供验证包及预设故障，限制局域网客户端。生产游戏仍只接受固定官方 HTTPS 来源；本地 HTTP 特例仅在这个独立调试应用中生效。

## 覆盖范围

验证版复用正式 `AppUpdater`、`AppUpdateManifest`、`AppUpdateInstaller`、`AppUpdateDialog` 和 Android 原生插件。仅替换了测试清单来源、允许的本地地址、超时时长和可用空间测试注入。版本检查的清单解析由正式组件单元测试覆盖；本验证版不请求线上清单。

这不是完整游戏的发布包，使用单独调试签名，同时包含 arm64 和 x86_64。完整游戏的正式签名、厂商系统差异和实际发布渠道仍需用正式包在目标手机验收。macOS 已恢复官网下载安装；Windows 继续保留游戏内更新及官网入口。

## 复现与回退

2026-09-19 第一轮验证：65 项 Godot 回归（清单 6、更新状态 14、检查更新 21、导出设置 24）、5 项清单生成测试、8 种弹窗布局通过。真实 TCP 连接“响应头后永不发送正文”的超时及取消回归通过，修复了旧线程模式取消时可能卡住界面的问题。下述 `android-validation` 目录是改用系统下载前的历史证据；新的后台下载记录见 [系统后台下载验收](android-background.md)。

Android 模拟器故障批次 11/11 通过，包括空间不足、404、无响应、短文件、半途断流、哈希损坏、不可解析 APK、缓存被删除、版本不符、下载中杀进程、恢复后正常下载。见 [实际状态记录](evidence/android-validation/android-scenarios.json)。空间不足为明确注入，其他文件和 HTTP 故障通过真实下载或原生组件执行。

最终交付包还在 **Android 16 / API 36 / x86_64** 模拟器完成了 4/4 原生流程：权限拒绝后重试、系统取消后重试、确认页杀进程后重试、通过系统确认真实覆盖安装 A→B。系统版本号确认为 `1.0.1 / 2`，数据标记仍是 `created-in-1.0.0`。见 [原生流程记录](evidence/android-validation/native-final.json) 与 [升级成功截图](evidence/android-validation/native-final.png)。未把模拟器结果表述为各品牌真机验收。

这些实际回归发现并修复了三个关键故障：停滞 HTTP 连接取消时卡住、安装写入流重复关闭导致会话撤销、杀进程重试时系统复用旧确认页。故障批次之后的原生修正由上述最终包原生流程重新验收。成品摘要见 [校验信息](evidence/android-validation/checksums.json)。

构建：`python tools/build_android_update_lab.py`。需要 Godot 4.6.1、对应导出模板、Android SDK 和 JDK 17；这些都是开发机工具，不是玩家依赖。

自动化异常验证：`tests/run_android_update_lab_checks.py`，必须明确指定设备。它只操作验证包，最终停在正常包已就绪，系统安装确认仍需单独执行。真实停滞连接回归：`tests/run_app_update_stalled_transport.gd`。

系统流程回归：`tests/run_android_update_lab_native.py`。该测试要求英文系统界面、已就绪的 B 包和显式参数 `--confirm-test-update`，会操作验证应用的安装权限与系统确认，覆盖拒绝后重试、取消后重试、确认页杀进程后重试、真实升级和数据保留。它通过当前系统界面的文字及位置定位按钮，不使用固定点击坐标。

原生安装按 [PackageInstaller.Session](https://developer.android.com/reference/android/content/pm/PackageInstaller.Session#commit(android.content.IntentSender)) 的要求，在提交前完成写入并关闭流；每次系统确认使用独立任务，避免 Android 重用已作废会话的确认页面。任务标志见 [Android Intent 文档](https://developer.android.com/reference/android/content/Intent#FLAG_ACTIVITY_MULTIPLE_TASK)。

测试输出在 `.tmp/update-lab-20260919/`。正式游戏版本号、包名及在线服务没有为验证而修改。回退本功能时按 [更新说明](README.md) 撤掉对应组件，不清空玩家数据，也不重置其他工作树修改。
